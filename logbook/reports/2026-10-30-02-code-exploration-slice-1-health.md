## 3. The tour

Each part lists what was shown, then the points raised at the time.

### 3.1 API startup

**Shown.**
- `wrangler.jsonc`: `main: src/index.ts`, `workers_dev: false`, `preview_urls: false`. The API has no public URL; the web's `API` service binding is the only way in.
- `src/index.ts`: `createApp()` runs once per isolate at module load. The Hono app is an `ExportedHandler`; the runtime calls `default.fetch` per request. Nothing is read or opened at startup.
- `src/app.ts`: `bodyLimit` is first and has no path, so it runs app-wide before routing. `.route("/", health)` mounts a sub-app that owns its paths. `.notFound` and `.onError` are settings, not middleware, so their place in the chain does not matter.
- A request: `bodyLimit` (read in Hono's source) calls `next()` with no body; trusts `Content-Length` when there is no `Transfer-Encoding`; otherwise streams and counts, and rebuilds the request if it fits. Then router → handler → `respond.ts`. `onError` logs the cause and returns `internal`/500 without `err.message`.

**Raised.**
- `new Hono()` has no `Bindings` type yet; nothing reads `c.env`. A C1/C2 question for slice 2.
- `createApp` takes no arguments; it is a factory with nothing to vary yet.
- Only the `Content-Length` path of `bodyLimit` is tested; the streaming path is not.
- `@hono/valibot-validator` is declared but not imported, unlike `result.ts`, which was left out for being unused.

### 3.2 `respond.ts` and the handlers

**Shown.**
- The status map `{ validation: 422, not_found: 404, limit: 409, too_large: 413, internal: 500 } as const satisfies Record<ErrorKind, ContentfulStatusCode>`: a new kind fails `check` until it has a status; `ContentfulStatusCode` excludes 204/304; not exported, because only the api needs it.
- `success(c, data, code = 200)`; `code` is there for slice 2's 201.
- `failure` overloads: `validation` requires `field`, other kinds refuse it, matching the contract's `ApiError`. `field` is left out when undefined.
- Handlers: one export per file, one expression each, importing only `respond.ts` and Hono types. `getHealth` touches no store (C2). `notFound` also answers a known path with the wrong method (`DELETE /health` is a 404; the PRD has no 405). `tooLarge` is `bodyLimit`'s `onError`; Hono does not export that slot's type (`OnError` is file-local). `onError` logs with `console.error("internal error", err)`.

| File | Typed as |
|---|---|
| `health.ts` | `(c: Context)` |
| `not-found.ts` | `NotFoundHandler` |
| `too-large.ts` | `(c: Context)` |
| `error.ts` | `ErrorHandler` |

**Raised.**
- `success<T>` accepts any `T`; nothing ties reply data to the contract at compile time. Only the integration parse would catch a wrong shape.
- The body of `failure` is not checked against `ApiError`; the guarantee comes from the overloads.
- Returning plain `Response` loses Hono's typed response, which matters only for Hono RPC (`hc`).
- Handler typing is mixed: two Hono named types, two bare `(c: Context)`.
- `onError` turns Hono's `HTTPException` into a 500. In slice 2 the validator throws `HTTPException(400, "Malformed JSON in request body")` (`hono/dist/validator/validator.js:18`), which would become `internal`.
- The log line has no request id, method or path; logging convention is open (F5, F7).
- The `console.error` stub in the unit test is never restored (no `restoreMocks`, no `mockRestore`).

Claude offered four changes (tie `success` to the contract, type `getHealth` as `Handler`, `restoreMocks: true`, record the `HTTPException` point). The owner did not take them up.

### 3.3 The envelope

The owner asked for a definition.

- The fixed outer shape of every JSON body the API sends (`prd/todo.md:178-185`), in two forms told apart by `ok`: `{ ok: true, data }` and `{ ok: false, error: { kind, message, field? } }`.
- `data` depends on the route; `error` is the same on every route. `kind` is one of five; `message` is display text and never carries the cause for `internal`; `field` appears only with `validation`.
- The status per kind is in the PRD and travels on the response, not in the body.
- Where it lives: schemas in `contract/src/envelope.ts`, built only in `api/src/respond.ts`, parsed in `web/src/lib/server/health.ts`.
- The one case the API cannot shape is a failure before the Worker runs (the binding call rejecting); the web treats that as "down".

**Correction made.** Claude had said earlier that the status per kind "is not in the contract". It is not in the `contract` package, but the PRD specifies it.

### 3.4 API tests

**Shown.**
- `vitest.integration.config.ts` uses `cloudflareTest` with the real `wrangler.jsonc`; tests run in workerd, and `exports.default.fetch` goes through the whole composition with nothing faked. Its type comes from `mainModule` in `worker-configuration.d.ts` (F15); `SELF` is deprecated.

| File | Request | Asserts |
|---|---|---|
| `health.test.ts` | `GET /health` | 200; parses as `envelope(HealthReply)`; equals `{ ok: true, data: { ok: true } }` |
| `not-found.test.ts` | `GET /nope` | 404; parses as `Failure`; kind `not_found` |
| `too-large.test.ts` | `POST /health`, `BODY_LIMIT_BYTES + 1` bytes | 413; parses as `Failure`; kind `too_large` |

- Every body goes through the strict contract schemas. `too-large` posts to `/health` so a 413 (not 404) shows the limit runs before routing (F1). Messages are never asserted.

**Raised.**
- `health` compares the whole body; the failure tests check `kind` and rely on the strict parse. Two styles.
- The `too-large` body is a string, so only the `Content-Length` path is tested.
- Integration uses bare `it`; the unit test uses `describe("onError")`.
- One `tsconfig.json` typechecks `src`, both test tiers and configs against Worker types, so a node unit test could typecheck a `cloudflare:workers` import that fails at runtime.
- Unit test files mirror source paths; integration files are named after routes.

### 3.5 Contract

**Shown.**
- `package.json` exports `./src/index.ts`; no build step. wrangler (esbuild) and Vite compile it.
- A schema and its type share a name.
- Nothing in it knows Hono, Workers or SvelteKit.
- `envelope.ts` top-down: `ErrorKind` picklist; `ApiError` variant on `kind`; `Failure`; `success(Data)`; `envelope(Data)` variant on `ok`. All `strictObject`.
- Tests: all 8 go through `envelope(HealthReply)` from `src/index.ts`, using `v.is`.

**Raised.**
- The four non-validation kinds are written twice (`envelope.ts:44` and `ErrorKind`). A kind added only to `ErrorKind` would pass the api's type check, be sent, and be parsed by the web as "down". Claude sketched deriving one list from the other.
- `success` names two things (F4). Claude suggested `Success`/`Envelope` in PascalCase to match `Failure` and `ApiError`.
- Contract tests accept only `validation`; `not_found` and `too_large` are accepted in integration.
- `message: v.string()` accepts `""`; the PRD does not say otherwise.

Claude asked whether to change the first two now. The owner answered: no changes; understanding first.

### 3.6 Web

**Shown.**
- `wrangler.jsonc`: `main: .svelte-kit/cloudflare/_worker.js` (adapter output), `assets` with `ASSETS`, `services: [{ binding: "API", service: "todo-api" }]`.
- `vite.config.ts` holds the Kit config; Kit 3 has no `svelte.config.js`.
- `package.json`: `#lib/*` (F3); depends on `@todo/contract` and `valibot`, not `@todo/api`.
- One request: the adapter's `worker.js` calls `server.init({ env })` at module load and `server.respond` per request, so bindings come from `cloudflare:workers`, not `event.platform` (F2). In `vite dev`, a virtual `cloudflare:workers` backed by `getPlatformProxy` resolves `env.API` to the `todo-api` running under `wrangler dev` through the dev registry.
- The load is one line. `readHealth` takes `Pick<Fetcher, "fetch">`, calls `https://todo-api/health` (host never resolved, kept for logs), and returns `down` in order: binding rejects, non-2xx, body not JSON, body not `envelope(HealthReply)` or a valid `Failure`; otherwise `up`. Each `try` covers one call; the load never throws.
- `Health` is the page's view model, so it lives in the web, not the contract.
- The page reads `data` with `$props()` and renders with escaped interpolation; "down" is content, not an HTTP error.
- Tests: unit with a fake `{ fetch }`, five cases asserting only the return value; e2e visits `/health`. Playwright starts the API on 8787, then the web on 5173, each waiting for `/health` (F10). No web integration tier (C5).

**Raised.**
- The `|| !body.ok` branch (a 2xx `Failure`) has no case.
- The unit test imports by relative path; the load imports by `#lib`.
- `reuseExistingServer: false` makes `test:e2e` fail on a port clash with a running `pnpm dev`.
- Every `down` is silent (F7).

The system in one line: browser → `todo-web` (adapter → Kit → load → `readHealth`) → `API` binding → `todo-api` (bodyLimit → router → handler → `respond`) → envelope → parsed against the contract → `up`/`down` → page.
