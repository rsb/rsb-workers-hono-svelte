## 0. Things found while reading the installed packages

1. **adapter-cloudflare 8 has no `event.platform`.** Its `worker.js`
   passes `env` from `import { env } from "cloudflare:workers"` to
   `server.init`, and in dev a virtual `cloudflare:workers` module
   backed by `getPlatformProxy` stands in. So a load reaches the `API`
   binding through a module import, not through its event.
   **Consequence:** the page load cannot be handed a fake binding as an
   argument. **Proposal [you]:** the load is one line,
   `readHealth(env.API)`, and `readHealth` lives in
   `src/lib/server/health.ts`, taking the binding as a parameter. The
   unit test calls `readHealth` with a fake binding. Rejected: aliasing
   `cloudflare:workers` to a fake module in the unit config (a module
   mock in disguise, and it ties the unit tier to a runtime module
   name).
2. **`@cloudflare/vitest-plugin` deprecates `SELF`.** The replacement is
   `import { exports } from "cloudflare:workers"` and
   `exports.default.fetch()`. **[detail]** Use `exports`; it needs the
   generated `mainModule` type, which `wrangler types` writes once
   `src/index.ts` exists.
3. **Hono exports `Context` as a class.** `new Context(new Request(url))`
   builds a real context in node, so an exported handler can be unit
   tested without a fake context. **[detail]**
4. **Playwright's `webServer.url` treats 404 as not ready.** The web
   server has no `/` route in slice 1, so its readiness URL becomes
   `/health`, which also proves the binding before any test runs.
   **[detail]**

## 1. Contract (`apps/todo/contract`)

```
src/index.ts      re-exports, nothing else
src/envelope.ts   ErrorKind, ApiError, Failure, success(), envelope()
src/health.ts     HealthReply
src/limits.ts     BODY_LIMIT_BYTES = 8 * 1024
test/unit/envelope.test.ts
```

- **[detail]** A schema and its type share a name (`ApiError` the
  schema, `ApiError` the `v.InferOutput` type), the valibot idiom.
- **[detail]** `ApiError` is a variant on `kind`: `validation` requires
  `field`, every other kind forbids it. The PRD says `field` appears
  "when the kind is `validation`", and the schema can state that.
- **[detail]** `success(data)` and `envelope(data)` are schema
  factories, so each reply's envelope is built from its data schema
  (`envelope(HealthReply)`), never written out by hand.
- **[you]** The HTTP status per kind is not in the contract. The web
  reads `ok` and `kind`; only the api needs the status, so it lives
  with the api's response building (C4's reasoning: no shared surface
  without a consumer).
- Unit tests: the envelope schema, one case per way a body can fail
  (not an object, `ok` missing, unknown kind, `validation` without
  `field`, `field` on another kind), then success and error accepted.

## 2. API (`apps/todo/api`)

Parts from handoff 00 in brackets.

```
src/index.ts              [1a] export default createApp()
src/app.ts                [1b] createApp(): bodyLimit, routes, notFound, onError
src/routes/health.ts      [2]  GET /health → getHealth
src/handlers/health.ts    [6]  getHealth
src/handlers/not-found.ts [7]  notFound
src/handlers/too-large.ts [7]  tooLarge
src/handlers/error.ts     [7]  onError: logs the cause, returns `internal`
src/respond.ts            [6]  success(c, data, status?) and failure(c, kind, message, field?)
test/unit/handlers/error.test.ts
test/integration/health.test.ts
test/integration/not-found.test.ts
test/integration/too-large.test.ts
```

- **C1** api imports `@todo/contract`, `hono` and `valibot` only.
  `routes → handlers → respond`; no operation and no data port yet
  (C2, C3).
- **C2** `getHealth` returns `success(c, { ok: true })` and touches no
  store.
- **C3** One named export per handler file. `notFound`, `tooLarge` and
  `onError` are handlers too, exported, and registered only in
  `app.ts`.
- **C4** `src/result.ts` is **not** written in slice 1: nothing returns
  a `Result` until slice 2's first operation, and an unused module
  would be the first dead code. The decision stands; slice 2 realizes
  it. **[you]** if you want the file now so C4 can be reviewed against
  code.
- **[detail]** `respond.ts` holds the kind → status map
  (`satisfies Record<ErrorKind, ContentfulStatusCode>`), so a new kind
  in the contract is a type error in the api until it has a status.
- **[detail]** `bodyLimit({ maxSize: BODY_LIMIT_BYTES, onError: tooLarge })`
  is registered first, app-wide, so it runs before routing: an
  oversized body to an unknown path is a 413, not a 404. The test
  posts 8 KiB + 1 byte to `/health`.
- **[detail]** `onError` logs with `console.error("internal error", err)`
  and returns the message `"internal error"`. It never reads
  `err.message`.
- `index.ts` is the only file that may import an adapter (C1); there is
  none yet.

Tests:
- **Unit** `onError` only. It is the one handler the composition cannot
  reach in slice 1 (no route throws), so it is unit-tested through its
  own export (handoff 00 correction). One case: given an error whose
  message is a secret, the response is 500 `internal` and the body
  does not contain the secret. The log is silenced with a stub, not
  asserted (asserting a call would be a mock, a finding).
- **Integration** one route each, through `exports.default.fetch`:
  `GET /health` 200, `GET /nope` 404 `not_found`, `POST /health` with
  8193 bytes 413 `too_large`. Each asserts status and the parsed body
  against the contract's envelope.
- No unit test for `getHealth`, `notFound` or `tooLarge`: the
  integration tier already proves each, and the policy says no
  re-proving across tiers.

## 3. Web (`apps/todo/web`)

```
src/lib/server/health.ts      readHealth(api): Promise<{ api: "up" | "down" }>
src/routes/health/+page.server.ts  load = () => readHealth(env.API)
src/routes/health/+page.svelte     "The API is up." / "The API is down."
test/unit/health.test.ts
e2e/health.test.ts
```

- **C1** web imports `@todo/contract` and never `@todo/api`.
- **C5** No integration tier: no config, no script.
- `readHealth` declared failures, in the order the code hits them:
  1. the binding call rejects → down
  2. the response is not 2xx → down
  3. the body is not JSON → down
  4. the body is not `envelope(HealthReply)` → down
  then success → up. Each is a returned value; the `try` around
  `fetch` and `json()` turns a throw into `down` (errors on the request
  path are values).
- **[detail]** The binding URL is `https://todo-api/health`. A service
  binding ignores the host; the name is there for logs.
- **[detail]** The page does not show why the API is down. The reason
  is not the user's business, and showing it would echo the API's
  error text into HTML.
- **Unit** five cases, the four above then up, with a fake binding
  (`{ fetch }` returning a fixed `Response` or rejecting). A fake, not
  a mock: nothing asserts it was called.
- **E2E** scenario 1.1 only.

## 9. Changes made while writing

1. **Kit 3 removed `$lib`.** Importing `$lib/...` is a build error
   that points at `#lib`, a Node subpath import. `web/package.json`
   gets `"imports": { "#lib/*": "./src/lib/*" }` and the load imports
   `#lib/server/health.ts` (with the extension, as everywhere else in
   the repo). Findings F3, profile-notes P30.
2. **web depends on valibot directly.** `readHealth` parses the reply
   with `v.is`, and pnpm does not hoist the contract's dependency, so
   `valibot: catalog:` is added to web's `dependencies`. P25 now names
   the web too.
3. **Contract schemas are `strictObject`**, not `object`: forbidding
   `field` on a non-validation kind needs unknown keys rejected, and
   the same then holds for every envelope. The contract test gained a
   case (data that does not match the reply).
4. **Playwright's chromium was not in the cache.** 1.64.1 wants build
   1248; the cache has up to 1243, `~/.cache` is not writable from
   the sandbox and the CDN is not on the allowlist. For this run only,
   `PLAYWRIGHT_BROWSERS_PATH=$TMPDIR/pw-browsers` with build 1243
   linked under the name 1248. Nothing in the repo changed. Findings F9.
5. **No other change.** The file list in §1–§3 is what was written.
