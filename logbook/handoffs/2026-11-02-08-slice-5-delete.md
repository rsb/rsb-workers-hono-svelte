   - **Naming.** The UI says "Mark all as complete". The API is
     `PATCH /todos`. Following slice 5 Q2, the two may differ. Which
     names do the body, the operation, the port method and the action
     use (for example `PatchTodosBody`, `setAllCompleted`, `markAll`)?
   - **The body.** A new `v.strictObject({ completed: v.boolean(…) })`,
     with the message "completed must be true or false" as in
     `PatchTodoBody`. A missing `completed` is a 422 with
     `field: "completed"`.
   - **The reply.** The PRD says "200 all todos", so `TodoListReply`
     can be reused. Confirm.
   - **The store, and its order.** `RETURNING` cannot be ordered, and
     the list is in `seq` order. Options:
     - `db.batch([update, select])`, which D1 runs as one transaction;
     - the store's `UPDATE`, then the operation calls `listTodos`;
     - the operation returns nothing, and the BFF reloads anyway.
     Which one, and is the update and the read one atomic step?
   - **The form, inside another form.** The design puts the button in
     the new-todo line, which is inside the add form. HTML does not
     allow a form inside a form. Options:
     - a separate `?/markAll` form outside the add form, with the
       button joined to it by its `form` attribute;
     - a submit button with `formaction="?/markAll"` in the add form,
       so the add form's `SubmitFunction` sees both actions and the
       title is sent too;
     - restructure `NewTodo` so the line holds two sibling forms.
   - **What the button sends.** As toggle does, it sends the new
     value, not "flip it": `completed` = not every todo completed,
     worked out when the page was rendered. So sending it twice is
     safe. Confirm.
   - **Where the pressed state comes from.** `NewTodo` needs to know
     whether there are todos and whether all are done. Is that worked
     out in `load-todos.ts` (as `active` is) and passed down, or in
     the page from `data.todos`?
   - **Without JS.** A plain form post, as toggle and remove are, so
     it works without JS. Confirm.
   - **With JS, when do the rows change?** Either every row shows the
     new value at once (pending, as toggle does, which needs the
     pending state lifted out of `TodoItem`) and the button too, or
     everything waits for the reply.
   - **A failed mark-all.** There is no error place near the button.
     Options: the new-todo error line (which "each form keeps its own
     failure" would then share), a new message under the line, or a
     reload with no message.
   - **Mark all while a row is being edited.** Clicking the button
     blurs the edit input, which saves the edit first. Two posts then
     run. Check this order is safe, and say what the page shows.
   - **E2e "given two active todos".** Mark all changes every todo in
